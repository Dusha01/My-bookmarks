## 1. Образ vs контейнер

| Понятие | Аналогия | Живёт где |
|---------|----------|-----------|
| **Image (образ)** | Установочный ISO / шаблон | Локальный кэш + registry (Docker Hub и др.) |
| **Container (контейнер)** | Запущенный экземпляр из шаблона | Процесс на хосте + своя FS поверх образа |

```text
образ  ──docker run──►  контейнер (можно много штук из одного образа)
nginx:1.27                 nginx_proxy
                           nginx_test
```

- Удалить контейнер ≠ удалить образ  
- Удалить образ нельзя, пока на него ссылаются контейнеры (stopped тоже считаются)

## 2. Нейминг и теги

Формат ссылки на образ:

```text
[registry/][namespace/]repository[:tag]
```

Примеры:

| Ссылка | Что значит |
|--------|------------|
| `nginx` | Docker Hub, official, тег по умолчанию `latest` |
| `nginx:1.27` | Конкретная мажор.минор версия |
| `nginx:1.27-alpine` | Вариант на Alpine |
| `certbot/certbot:v2.11.0` | Namespace `certbot`, репозиторий `certbot` |
| `ghcr.io/org/app:1.2.3` | GitHub Container Registry |

### Правила хорошего тона

- **Не полагайся на `latest` в проде** — тег «плавает», завтра можешь получить другой билд  
- Фиксируй версию: `nginx:1.27`, `postgres:16.4`  
- Имя контейнера (`--name` / `container_name`) — уникально на хосте  
- Имена сервисов в Compose — DNS-имена внутри сети проекта  

### Имена контейнеров

```bash
docker run --name nginx_proxy ...
# или в compose:
container_name: nginx_proxy
```

Без `--name` Docker сам сгенерирует что-то вроде `funny_einstein`.

## 3. Слои и Dockerfile (идея)

Образ = набор **слоёв** (read-only). Контейнер добавляет тонкий writable-слой сверху.

```dockerfile
FROM nginx:1.27          # базовый образ
COPY conf /etc/nginx     # новый слой
RUN apt-get update && …  # ещё слой
```

Зачем понимать:

- одинаковые слои **шарятся** между образами → экономия места  
- частый `RUN apt-get` без очистки раздувает образ  
- порядок инструкций влияет на кэш сборки  

Для большинства VPS-задач ты **берёшь готовый образ**, а не собираешь сам — но теги и размер (`alpine` vs полный) всё равно важны.

## 4. Порты

Публикация порта: **`host:container`**

```bash
docker run -p 8080:80 nginx:1.27
#          │     │
#          │     └── порт внутри контейнера (nginx слушает 80)
#          └── порт на хосте (откроешь http://IP:8080)
```

| Запись | Смысл |
|--------|--------|
| `-p 80:80` | Хост 80 → контейнер 80 |
| `-p 127.0.0.1:5432:5432` | Доступен только с localhost хоста |
| `-p 443:443` | HTTPS на хосте |
| без `-p` | Порт виден **только** внутри docker-сети |

В Compose:

```yaml
ports:
  - "80:80"
  - "443:443"
```

> ⚠️ `-p` открывает порт на хосте. Дальше всё равно нужен UFW/фаервол.  
> Для сервисов «только для nginx» часто **не** публикуют порты наружу — только общая сеть.

## 5. Тома и данные

Контейнер эфемерен: удалил — writable-слой пропал. Данные, которые нужны жить дольше:

| Способ | Пример | Когда |
|--------|--------|--------|
| **Bind mount** | `./nginx.conf:/etc/nginx/nginx.conf:ro` | Конфиги с хоста, логи в `/var/log/...` |
| **Named volume** | `pgdata:/var/lib/postgresql/data` | БД, данные приложения |
| **tmpfs** | в памяти | Секреты/кэш, не на диск |

```bash
# bind
-v /var/log/nginx/example.com:/var/log/nginx/example.com

# named volume
-v pgdata:/var/lib/postgresql/data
```

Флаг `:ro` — только чтение (удобно для конфигов и сертификатов у nginx).

```text
Хост                    Контейнер
./certbot/conf    →     /etc/letsencrypt
./nginx.conf      →     /etc/nginx/nginx.conf
```

## 6. Сети

Контейнеры в одной сети видят друг друга по **имени** (DNS):

```text
nginx  ──proxy_pass http://backend:8000──►  контейнер backend
```

| Тип | Зачем |
|-----|--------|
| `bridge` (default) | Обычная сеть на одном хосте |
| `bridge` + user-defined | DNS по имени контейнера/сервиса |
| `external: true` | Сеть уже создана (nginx + несколько проектов) |
| `host` | Сетевой стек хоста (редко, осторожно) |

```bash
docker network create app-net
docker network connect app-net nginx_proxy
```

В Compose сервисы одного файла попадают в общую сеть проекта автоматически.  
Для связи **разных** compose-проектов — общая `external` сеть (как в [nginx](../nginx/nginx-docker.md)).

## 7. Restart policy

| Политика | Поведение |
|----------|-----------|
| `no` | Не перезапускать |
| `always` | Всегда, даже после ребута демона |
| `unless-stopped` | Как always, но не после ручного `stop` |
| `on-failure` | Только при ненулевом exit code |

На VPS обычно:

```yaml
restart: unless-stopped
```

## 8. Права и безопасность (минимум)

- Группа `docker` ≈ права root на хосте — не раздавай всем  
- Не монтируй docker.sock в контейнеры без нужды  
- Секреты не клади в образ и не коммить в git; лучше env-файл с правами `600` или secrets  
- Наружу публикуй минимум портов; остальное — через reverse-proxy  
- Обновляй образы осознанно (`docker pull` + recreate), не «автоматом latest»
